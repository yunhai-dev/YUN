## 小米发布Xiaomi-Robotics-1两阶段机器人模型 {#news-4}

> **小米**发布`Xiaomi-Robotics-1`，采用无具身UMI预训练与真实机器人数据后训练相结合的两阶段方法。其预训练数据覆盖10万小时轨迹和超过1,700个场景。

![小米发布Xiaomi-Robotics-1两阶段机器人模型](https://robotics.xiaomi.com/robot-static-resource/xiaomi-robotics-1/pretrain_data.jpg)

`Xiaomi-Robotics-1`先进行大规模无具身UMI预训练，再结合真实机器人数据后训练。预训练数据涵盖家庭、商业场所、工业场地及户外空间。

小米开发自动标注流程，将轨迹切分为固定长度片段，并为每个片段标注描述场景状态转换的语言信息。

后训练使用跨具身数据集，包括内部机器人数据、筛选后的开源机器人数据及高质量UMI数据。内部数据包含超过7,200小时真实家庭环境数据。

相关任务包括整理沙发、整理鞋柜及收纳厨房用品。小米报告称，随数据量和模型规模增长，预训练验证动作误差持续下降；该结果未见独立验证信息。

[查看原文](https://robotics.xiaomi.com/xiaomi-robotics-1.html)

## CocoIndex推出长周期智能体增量上下文引擎 {#news-10}

> **CocoIndex** 将代码库、会议记录、收件箱等数据转为持续更新的上下文，供 AI 智能体与 LLM 应用使用。项目提供 Python API，并支持增量处理变化内容。

![CocoIndex推出长周期智能体增量上下文引擎](https://opengraph.githubassets.com/efb69affecc037df228d99f46d279fa3f1dc38d1dc495fe7702b7cef7158fc36/cocoindex-io/cocoindex)

**CocoIndex** 自称面向长周期智能体的增量引擎，可处理代码库、会议记录、收件箱、Slack、PDF 和视频等来源。

项目称，其通过最少的增量处理维持上下文更新。首次运行可进行回填，后续运行仅为发生变化的文件重新生成嵌入。

项目提供 Python API，可通过 `pip install -U cocoindex` 安装。示例中使用 `localfs` 读取本地目录，以 PostgreSQL 为表目标，并声明向量索引。

README 提供 20 多个示例，并称示例每周更新。仓库页面显示其获 10.9k Star、837 个 Fork，代码以 Rust 和 Python 目录组织。

项目关于“10 分钟让生产 AI agent 就绪”等时间表述属于项目方承诺，实际效果取决于使用场景。

[查看原文](https://github.com/cocoindex-io/cocoindex)

## SoundCloud升级AAC编码器，以17kHz截止换音质 {#news-14}

> **SoundCloud**称，其升级至 Fraunhofer `libfdk_aac` 的AAC编码器，在追踪的所有指标上带来更高感知音质。新转码音频的频谱在17 kHz处出现明显截止。

![SoundCloud升级AAC编码器，以17kHz截止换音质](https://developers.soundcloud.com/blog/static/c3deaa707b26e3482cc95abb9bbd9e16/8ff1e/native_vs_fdk_256k.png)

**SoundCloud**去年首次在十多年间升级AAC编码器，采用 Fraunhofer 的 `libfdk_aac`。

与旧编码器保留至20 kHz的频率能量不同，新编码器转码的音频在频谱图上会于17 kHz附近明显截止。

文章指出，AAC等有损压缩需要在固定比特数下，在不同频段之间分配编码比特。

**SoundCloud**表示，人耳对2至5 kHz最敏感，多数成年人即使在理想条件下也无法可靠感知17 kHz以上声音；削减最高频段可提升更广泛可听内容的准确度。

[查看原文](https://developers.soundcloud.com/blog/less-is-more-why-soundcloud-low-passes-its-aac-transcodings/)

## Cortex发布DRIVE框架衡量AI时代工程组织健康度 {#news-15}

> **Cortex**联合创始人兼 CTO Ganesh Datta 介绍`DRIVE`框架，用五个支柱评估 AI 时代工程组织的健康状况。该框架旨在衡量团队能否持续将客户需求转化为可靠软件。

![Cortex发布DRIVE框架衡量AI时代工程组织健康度](https://a-us.storyblok.com/f/1021527/1200x600/b5d7e1f131/framework_meta_image.webp)

`DRIVE`由 Delivery、Reliability、Initiatives、Vigilance 和 Efficiency 五个支柱构成，并包含定期审查机制，以将测量结果转化为行动。

Delivery 关注交付速度及其可持续性，所列关键指标包括部署频率、变更交付周期和随叫随到告警量。

Reliability 关注组织是否兑现对客户的承诺，指标包括功能性 SLO 状态，以及`Sev0`和`Sev1`事件数量。

Initiatives 则关注由工程团队推动的组织范围投资是否取得进展。

[查看原文](https://www.cortex.io/drive)
