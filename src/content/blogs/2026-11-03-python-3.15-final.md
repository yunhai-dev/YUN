6 月写过一篇 [Python 3.15 Beta 预览](./2026-06-15-python-3.15)，那时候还是 Beta 2，很多特性都还带着"可能会改"的尾巴。

现在定稿了。**Python 3.15.0 于 2026 年 10 月 9 日正式发布**，5,643 个提交、1,012 位贡献者。按 [PEP 790](https://peps.python.org/pep-0790/) 的排期走（之前 Beta 文里我写成了 PEP 745，那是 3.14 的排期，这里纠正一下），发布经理还是 Hugo van Kemenade，维护到 2031 年 10 月。现在连 3.15.2 都已经出来了，可以放心升了。

这篇文章不重复抄一遍手册，只讲正式版确认落地的东西：哪些是真来了，哪些 Beta 之后有变化，升级前要改什么。

## 概览

正式版最大变化，一句话就是：**启动更快、内存表示更干净、排查性能更容易**。

- [**延迟导入终于来了**](#section-lazy-imports) — PEP 810，`lazy import` 首次使用时才加载
- [**两个新内置类型**](#section-builtins) — PEP 814 `frozendict` + `sentinel`
- [**推导式里可以用解包了**](#section-unpacking) — PEP 798，`[*L for L in lists]`
- [**Tachyon 采样分析器**](#section-tachyon) — PEP 799，百万赫兹采样，几乎零开销
- [**注解延迟求值 + UTF-8 默认**](#section-semantics) — PEP 649/749、PEP 686，语义层面的两刀
- [**JIT 更快了**](#section-perf) — 官方数据 x86-64 Linux 几何平均 7-8%，AArch64 macOS 11-12%
- [**升级前必看的废弃**](#section-deprecation) — `profile`、`sre_*`、`__version__` 都在清理名单上

---

## 一、先说结论：要不要升？

要，但分两步。

如果你是做 CLI、Serverless、桌面应用，对启动时间敏感，3.15 的延迟导入 + JIT 提速是实打实的收益，直接升。如果你在维护 C 扩展或者重度依赖 `__annotations__`、`re.match`、平台默认编码的老项目，先看第五节，把废弃项扫一遍再升。

```bash
uv self update
uv python install 3.15
uv tool install ruff@latest
```

升完跑一遍：

```bash
ruff check --select UP --target-version py315 .
pyupgrade --py315-plus **/*.py
```

## 二、延迟导入：启动优化的正解 {#section-lazy-imports}

之前优化启动时间，做法都是往后挪 `import`、手写懒加载。3.15 给了官方解法：PEP 810 的 `lazy` 软关键字。

```python
lazy import json
lazy from pathlib import Path

print("应用启动中...")  # 到这里 json 和 pathlib 都还没加载

data = json.loads('{"key": "value"}')  # 第一次用到时才真正加载
```

几个关键点，正式版和 Beta 时一致：

1. 只在**模块作用域**有效，函数、类、`try` 块里不能用。
2. 不支持 `from module import *`，不支持 `from __future__`。
3. 全局开关照样有，适合先全量试水：

```bash
# 命令行
python -X lazy_imports=all app.py

# 环境变量
PYTHON_LAZY_IMPORTS=all python app.py
```

```python
import sys

sys.get_lazy_imports()
sys.set_lazy_imports("normal")
sys.set_lazy_imports_filter(lambda name: name.startswith("myapp."))
```

我的建议是：先在测试环境开 `all` 跑一遍，启动时间一般能掉一大截，没问题的模块再逐个改成显式 `lazy import`。做 CLI 工具的，这个特性几乎是白送的性能。

## 三、两个新内置类型：frozendict 和 sentinel {#section-builtins}

这是 3.15 给日常写代码最实在的东西。

### 1. frozendict

PEP 814。`list` 有 `tuple`、`set` 有 `frozenset`，`dict` 终于也有了不可变版本。

```python
>>> fd = frozendict(x=1, y=2)
>>> fd["x"] = 2
TypeError: 'frozendict' object does not support item assignment

>>> hash(fd)  # 键值都可哈希时，整体可哈希
>>> cache = {fd: "cached_result"}  # 终于可以直接当缓存 key 了
```

注意三点：

| 特性 | 说明 |
| --- | --- |
| **不是 dict 子类** | 直接继承 `object`，和 `dict` 是平行关系 |
| **顺序无关比较** | `frozendict(a=1, b=2) == frozendict(b=2, a=1)` |
| **保留插入顺序** | 迭代顺序和创建时一致 |

标准库这边 `json`、`pickle`、`pprint`、`copy` 已经适配了，剩下的还在陆续跟进。适合拿来做配置、函数默认参数、缓存 key，以前用 `MappingProxyType` 或者 `tuple(sorted(d.items()))` 绕路的地方都可以换掉了。

### 2. sentinel

另一个新内置，解决的是祖传痛点：以前写哨兵值只能 `MISSING = object()`，打印出来就是 `<object object at 0x...>`，调试时完全看不出是谁。

```python
MISSING = sentinel("MISSING")

print(repr(MISSING))  # MISSING，而不是 <object object at ...>
print(MISSING is MISSING)  # True，单例语义
```

配合函数默认值用起来最舒服：

```python
def get_user(uid, default=sentinel("default")):
    ...
```

以后在日志里看到 `MISSING`，一眼就知道是哪个哨兵，不用再去翻 `id()` 了。

## 四、推导式解包：少写一层循环 {#section-unpacking}

PEP 798。列表、集合、字典推导式和生成器表达式里，现在可以直接用 `*` 和 `**`。

```python
lists = [[1, 2], [3, 4], [5]]
[*L for L in lists]  # [1, 2, 3, 4, 5]

dicts = [{'a': 1}, {'b': 2}, {'a': 3}]
{**d for d in dicts}  # {'a': 3, 'b': 2}，后出现的覆盖先前的

sets = [{1, 2}, {3, 4}, {2, 3}]
{*s for s in sets}  # {1, 2, 3, 4}
```

对比一下以前的写法：

```python
# 3.14 及之前
result = [item for sublist in lists for item in sublist]

# 3.15
result = [*L for L in lists]
```

可读性提升很明显，展平、合并字典这种操作终于不用写双层循环了。

## 五、语义层的两刀：注解延迟求值 + UTF-8 默认 {#section-semantics}

这两个不显眼，但影响深远。

### 1. 注解延迟求值

PEP 649 + PEP 749。注解不再在 `def` 执行时立即求值，而是第一次被访问时才求值。

```python
def process(data: MyClass) -> MyClass:
    ...

class MyClass:
    pass

import typing
typing.get_type_hints(process)  # 到这里才真正求值，不再 NameError
```

好处有三：前向引用不用再套引号、`from __future__ import annotations` 可以慢慢退场、模块加载时少了一堆注解求值开销。但如果你有代码直接读 `__annotations__` 并假设它是求值后的对象，要重点测一下。

### 2. UTF-8 成为默认编码

PEP 686。`open()` 不再跟随平台默认编码（Windows 上曾经是 GBK/CP936 的坑），统一默认 UTF-8。

```python
open('file.txt')  # 永远是 UTF-8
open('file.txt', encoding='locale')  # 明确想要旧行为时这么写
```

跨平台项目建议全局搜一遍裸 `open()`，确认没有依赖系统编码的隐式行为。

## 六、性能与排查：JIT + Tachyon {#section-tachyon}

### 1. JIT 提速

3.15 的 JIT 是 3.13 引入以来最大的一次升级。官方 release notes 给的数字：**x86-64 Linux 几何平均快 7-8%，AArch64 macOS 快 11-12%**。Windows 64 位官方构建还开了尾调用解释器，GC 也从 3.13 的增量 GC 调回了分代 GC，内存开销更稳。

什么都不用改，升上去重跑一遍压测就能看到差异。

### 2. Tachyon：新的采样分析器 {#section-perf}

PEP 799 拆出了 `profiling` 包：

- `profiling.tracing` — 确定性跟踪，从 `cProfile` 迁过来，`cProfile` 保留为兼容别名
- `profiling.sampling` — 新的 Tachyon 采样器，最高 **1,000,000 Hz**，几乎零开销
- `profile` 模块正式废弃，3.17 移除

```bash
# 默认 wall 时间采样
python -m profiling.sampling my_script.py

# 火焰图、pstats、折叠格式、Firefox Profiler 格式都支持
python -m profiling.sampling --flamegraph my_script.py
python -m profiling.sampling --pstats my_script.py
python -m profiling.sampling --collapsed my_script.py

# 直接 attach 到跑着的进程
python -m profiling.sampling attach --pid 12345

# 实时 TUI
python -m profiling.sampling --live my_script.py
```

以前性能问题靠猜，现在直接百万赫兹采样 + 火焰图，瓶颈藏不住。`profile` 还在用的，趁这次迁到 `profiling.tracing`。

## 七、标准库与体验小改进

正式版里还有一批"小而顺手"的：

- **`re.prefixmatch()`** — `re.match()` 软废弃，新 API 命名更准确，老代码不用急着改，但新代码建议用新的
- **`asyncio.TaskGroup.cancel()`** — 终于可以提前取消整个任务组
- **`tomllib`** — 支持 TOML 1.1.0，内联表换行、十六进制转义都行了
- **`subprocess.Popen.wait()`** — Linux 用 pidfd、macOS 用 kqueue，不再轮询，CPU 零开销等待
- **错误提示更聪明** — `my_list.push(42)` 会提示 `Did you mean '.append()'?`，`toUpperCase` 会提示 `.upper()`，跨语言写串了也能被接住
- **到处都是彩色** — `ast` dump、`difflib`、`pickletools`、`sqlite3`、`http.server` 日志全支持了颜色，`NO_COLOR=1` 可关

## 八、升级前必看：废弃与移除 {#section-deprecation}

这一节是升级 checklist，建议照着扫一遍：

| 项目 | 状态 | 替代方案 |
| --- | --- | --- |
| `profile` 模块 | 废弃，3.17 移除 | `profiling.tracing` |
| `re.match()` / `Pattern.match()` | 软废弃，无移除计划 | `re.prefixmatch()` |
| 各模块的 `__version__` | 废弃 | `sys.version_info` |
| `sre_compile`、`sre_constants`、`sre_parse` | 移除 | `re` |
| `PyGILState_Ensure/Release` | 软废弃 | PEP 788 新 API |
| tarfile 多个 CVE | 已修复，建议必升 | CVE-2025-4138/4330/4435 |

另外 C 扩展作者注意：PEP 803 的 free-threaded abi3t（`Py_TARGET_ABI3T`）、PEP 697 的新类型 API，这次不跟进下次就要还技术债了。

## 总结

6 月那篇是"看看未来"，这篇是"可以动手了"。

我的升级顺序建议：

1. 本地先升 3.15，跑通测试，重点看 `__annotations__` 和裸 `open()`。
2. CLI / Serverless 项目开 `-X lazy_imports=all` 测启动收益。
3. 把 `object()` 哨兵换成 `sentinel`，把展平双循环换成推导式解包。
4. `profile` 迁到 `profiling`，性能问题用 Tachyon 重新看一遍。

Python 3.15 不是那种"重写语法"的大版本，但延迟导入、不可变字典、采样分析器这三件套，每一个都是能直接省时间、省 CPU 的东西。值得升。
