## Google 研究人员提出方法抑制 AI 代理记忆测试任务 {#news-2}

> Google 研究人员提出名为 `RRSI` 的方法，用于抑制自我改进型 AI 代理对测试任务的记忆效应。

![Google 研究人员提出方法抑制 AI 代理记忆测试任务](https://the-decoder.com/wp-content/uploads/2026/10/rrsi-google-generated-image-nano-banana-pro.jpg)

自我改进型 AI 代理可能记忆测试任务，导致其在新任务上的性能提升缩小或消失。

文中称，`RRSI` 让代理在未见过的基准测试上的得分最高提升 4.7 分。

文中还称，与未进行正则化的版本相比，`RRSI` 的令牌使用量约减少 30%。

上述结果为文章概括性描述，文中未提供具体基准测试、实验设置或统计细节。

## NASA与IBM发布开源月球基础模型，训练数据来自17年轨道观测 {#news-3}

> **NASA** 和 **IBM** 发布了面向月球科学的开源 AI 模型 Lunar Foundation Model。该模型使用近 200 万个图块数据包训练，数据主要来自月球勘测轨道飞行器 17 年的观测。

![NASA与IBM发布开源月球基础模型，训练数据来自17年轨道观测](https://the-decoder.com/wp-content/uploads/2026/10/nasa-ibm-research-moon-crater-ice-nano-banana-pro.jpg)

Lunar Foundation Model 是面向月球科学的开源 AI 模型之一。

模型训练数据主要来自月球勘测轨道飞行器长达 17 年的数据，共包含近 200 万个图块数据包。

在相关测试中，与表现最强的模型相比，该模型将极区冰沉积物预测误差最多降低了 22%。

文中未说明具体测试数据集、评估方法或这一结果的适用范围。

## GitHub 项目 text-to-cad 让代理具备 CAD 技能 {#news-8}

> GitHub 上的 **earthtojake/text-to-cad** 是一个代理技能库，可从本地项目文件生成、检查、寻找、切片并交接 CAD 和机器人描述文件。

![GitHub 项目 text-to-cad 让代理具备 CAD 技能](https://opengraph.githubassets.com/91e723682b51fd189d8f92c5b31206ebb79dd01c5583b49f8255829925479f0b/earthtojake/text-to-cad)

项目可根据自然语言或图像请求创建和编辑 CAD 模型，主要输出 STEP，也可选择导出 STL、3MF 和 GLB。

仓库还包含寻找 STEP 零件、生成工程图、创建 DXF 图纸，以及编写 URDF、SRDF 的技能。

其功能还包括创建 SDF 仿真模型与世界、DfAM 检查、DFM 审查、G-code 切片等。

页面显示该仓库有 1,421 次提交、约 1.7k 个 Fork 和 16.7k 颗 Star；说明建议从 main 分支安装或克隆。

## GitHub 热门项目：ARTEX 提供 AI 自主渗透测试能力 {#news-9}

> **ARTEX** 是一个采用 Go 后端和 Next.js 前端的 AI 自主渗透测试系统，提供任务执行、资产管理和人在环路等功能。

![GitHub 热门项目：ARTEX 提供 AI 自主渗透测试能力](https://opengraph.githubassets.com/c30a00367eb65918091a54447718537494df021066ef60e40f4cfcb49a4e50fc/Autumn-27/ARTEX)

项目提供仪表盘、任务列表、资产覆盖图、流量录制、人在环路对话、Agent 管理、LLM 配置和拦截审批等功能。

ARTEX 支持从 ScopeSentry 同步资产数据，并可按项目或任务选择域名、子域、IP、端口、站点和端点等资产类型。

安装依赖 PostgreSQL，探索功能需要配置 LLM，可使用 `ANTHROPIC_API_KEY` 或 `OPENAI_API_KEY`，也可在界面中配置。

项目支持一键安装脚本、Docker Compose、预编译二进制和源码编译单二进制；安装后默认通过 `http://localhost:8787` 访问，首次进入需在 `/setup` 设置管理员密码。

ARTEX 支持远程 MCP，可选择 Streamable HTTP 或旧版 SSE 方式；具体配置依赖运行环境及凭据。

[查看原文](https://github.com/Autumn-27/ARTEX)

## GitHub 热门项目：Caddy 提供自动 HTTPS 的多平台 Web 服务器 {#news-10}

> **Caddy** 是支持 HTTP/1、HTTP/2 和 HTTP/3 的可扩展多平台 Web 服务器，默认使用 TLS，并将自动 HTTPS 作为主要特性。

![GitHub 热门项目：Caddy 提供自动 HTTPS 的多平台 Web 服务器](https://repository-images.githubusercontent.com/29207621/a110cd80-a7df-11ea-8184-27bb6573a7fa)

项目支持通过 Caddyfile 配置，也支持原生 JSON 配置和 JSON API 动态配置。

面向公共域名时，Caddy 可使用 ZeroSSL 和 Let’s Encrypt；针对内部名称和 IP 地址，则可提供托管的本地 CA。

Caddy 支持在集群中协调多个实例，并提供多签发者回退和 Encrypted ClientHello（ECH）支持。

项目可运行于 macOS、Linux 和 Windows。

[查看原文](https://github.com/caddyserver/caddy)

## GitHub 热门项目：Nasiko 统一管理编码智能体运行数据 {#news-11}

> **Nasiko** 将自己定位为面向智能体、编码工具、框架及相关工具的 OpenRuntime，可发现已运行的编码智能体并展示其成本。

![GitHub 热门项目：Nasiko 统一管理编码智能体运行数据](https://opengraph.githubassets.com/95c2829456d82f49aab60b785252f35bcab6ed3df981051a30e09e4e9b9ebd00/Nasiko-Labs/nasiko)

Nasiko 可按 harness 和模型展示编码智能体成本，并将支出统一到一个数据模式中，同时将模型选择交还给使用者。

项目提到的编码智能体包括 Claude Code、Codex、Cursor 和 OpenCode，但原文未说明所有智能体均已支持。

其非侵入式发现功能可在不修改现有配置的情况下检测已运行的 harness。报告和路由功能需要显式选择加入，可能添加钩子或更新 harness 设置。

Nasiko 提供仅使用 Docker 的快速启动方式，不要求安装 Rust。
